# 外部系统接入：开发交付与使用

日期：2026-09-07。对应方案：[双入口接入方案](外部系统API接入方案.md)。

本版提供嵌入式问数页面和服务端 API 两种入口，共用既有模型、语义层、数据源与安全查询执行。目标业务系统的域名、用户标识和身份设施尚未提供，因此交付通用接入能力、SDK 与本机验证宿主，实际目标系统需按本文登记后联调。

## 已实现

2026-09-08 易用性更新：管理页增加三步指引、应用搜索与选中状态、普通用户分页加载、来源格式整理、字段校验说明、保存反馈、密钥复制和轮换确认、未保存修改提示，以及基于已保存配置的 API 自检/嵌入示例与排错速查。新增管理员 `POST /api/v1/integrations/check`，接收与创建应用相同的配置体，检查权限上限用户、主题发布和查询授权，返回逐主题结果及来源/能力/额度提示；检查不创建应用、不执行 SQL、不调用模型。完整启动步骤见 [系统启动教程](系统启动教程.md)。

- 管理入口 `/integrations`：应用创建、主题和能力授权、额度、启停、密钥轮换、RSA 身份声明配置、外部用户映射和审计。
- 独立公共接口 `/api/integration/v1`，支持结构化查询、自然语言问数、澄清/追问、任务状态、结果、取消、结果分析子任务和独立 OpenAPI。
- `/embed/ask?client_id=...` 专用页面和 `/lightsql-embed.js` SDK；支持主题锁定、标题/欢迎语/浅深色配置、历史会话、图表、来源说明和分析。
- 应用与用户双重隔离：每个应用/外部主体拥有独立代理执行身份，权限取该内部用户与应用权限上限用户的交集。执行代理不可作为映射来源，不允许管理员作为应用执行主体。
- 外部令牌具备独立签发方、受众与类型校验，不能登录内部管理 API；内部登录令牌也不能调用集成 API。
- 嵌入票据 60 秒有效且只能消费一次；绑定应用、主体、来源、主题和 iframe 随机挑战。浏览器会话令牌仅保存在 iframe 内存，不放入 URL 或内部登录存储。
- 持久化编排 Worker；底层 SQL 使用既有查询 Worker。请求幂等、运行中撤权复核、真实取消状态、分析失败保留已成功查询的数据、模型不确定结果不自动重试。
- SQL 每用户执行额度在内部账号及其各应用代理之间共享，不能借多个应用身份扩大该用户的查询并发。

## 1. 启动与升级

迁移版本：`50620ca515f5`，新增七张集成表，无已有业务表删除或字段修改。

正式环境先沿用现有元数据库备份流程，在相同版本的 API 和 Worker 启动前运行：

```bash
cd backend
python -m alembic upgrade head
python -m app.modules.integration.worker
```

查询执行仍需 `python -m app.modules.query.worker`。`compose.yml` 已增加 `integration-worker`，与后端共用镜像和环境变量。已有主机部署需要重启 API 与查询 Worker，以加载新的执行权限复核；集成 Worker 单独启动。生产入口使用 HTTPS。

本项目本机演示命令：

```powershell
.venv/Scripts/python.exe scripts/module1_demo.py migrate
.venv/Scripts/python.exe scripts/module1_demo.py api
.venv/Scripts/python.exe scripts/module1_demo.py query-worker
.venv/Scripts/python.exe scripts/module1_demo.py integration-worker
```

每个长期进程使用单独终端或服务管理器。管理页：[外部系统接入](http://127.0.0.1:8000/integrations)。

前端同源生产构建应沿用仓库约定设置 `VITE_API_URL=/`，避免开发环境 `.env` 的 `http://localhost:8000` 被写入部署产物：

```powershell
$env:VITE_API_URL='/'
Set-Location frontend
npm run build
```

## 2. 登记接入应用

1. 先为一个普通内部用户配置主题成员资格和查询授权，该用户作为应用数据权限上限。不要使用管理员账号。
2. 管理员进入“外部系统接入”，选择开放主题和能力，填写接入应用名称。
3. 如需要嵌入，登记宿主完整来源，例如 `https://erp.example.com`，不带路径、通配符或末尾斜线。仅本机开发允许 `http://localhost:端口` / `http://127.0.0.1:端口`。
4. 保存后将 `client_id` 与仅展示一次的 `client_secret` 保存到业务后端的密钥配置中。
5. 固定应用调用使用保留主体 `$app`。个人问数需另行登记外部 subject 到内部普通用户的映射，并配置可信声明公钥。

能力值：`query` 指标查询、`ask` 自然语言问数、`explore` 自由探索、`analysis` 结果分析、`embed` 嵌入界面。自由探索须同时具备主题逐列授权与行范围。

默认额度：最多 3 项在途任务、每分钟 120 次已认证请求（包含状态/结果轮询）、滚动 24 小时 100 次模型调用预留。调用预留是保守计数，不能视为模型厂商的实际计费账单。底层全局 5、每源 2、每用户 1 的 SQL 执行额度保持生效。

应用配置变更会递增版本，旧令牌与旧任务授权快照失效。密钥轮换立即作废旧密钥与旧令牌，本版未实现双密钥宽限期。应用权限上限用户和已有身份映射不允许改绑到其他用户；需要改绑时创建新的应用/外部主体，避免旧结果归属转移。

## 3. 服务端调用 API

本版内置的是 **JSON 应用令牌接口**，使用 Client Credentials 的应用身份语义，不是完整 OAuth/OIDC 授权服务器，也不直接兼容第三方 IdP 的任意访问令牌。

```http
POST /api/integration/v1/token
Content-Type: application/json

{
  "grant_type": "client_credentials",
  "client_id": "<应用 UUID>",
  "client_secret": "<应用密钥>"
}
```

返回 `access_token`、`token_type=bearer`、`expires_in=900`。令牌与密钥仅在业务后端保存；浏览器嵌入请使用下一节的票据流程。

自然语言问数：

```http
POST /api/integration/v1/answers
Authorization: Bearer <access_token>
Idempotency-Key: <此次操作唯一标识>
Content-Type: application/json

{
  "topic_id": "<已发布主题 UUID>",
  "question": "2026年8月各区域净销售额是多少？",
  "mode": "metrics",
  "include_analysis": true
}
```

提交成功返回 HTTP 202 和 `task_id`、`conversation_id`、`status_url`。后台处理不阻塞提交请求。

| 接口 | 用途 |
|---|---|
| `GET /topics` | 当前身份可用主题 |
| `GET /topics/{id}/catalog` | 已授权指标与维度的业务目录 |
| `POST /queries` | 提交 `{topic_id, plan, include_analysis}`，plan 只接受标准指标计划 |
| `POST /answers` | 提交自然语言问题 |
| `GET /tasks` | 最近 50 项有效任务，按当前身份/嵌入范围过滤 |
| `GET /tasks/{id}` | 状态、会话版本、澄清信息 |
| `GET /tasks/{id}/result` | 表格、图表建议、分析、来源与有效期 |
| `POST /tasks/{id}/analysis` | 对已有结果提交分析子任务，需独立幂等键 |
| `POST /tasks/{id}/cancel` | 申请取消 |
| `GET /openapi.json` | 独立公共 OpenAPI，包含明确任务与结果响应模型 |

以上路径均相对于 `/api/integration/v1`。结果的金额及数值沿用十进制字符串协议，请勿先转换为 JavaScript Number 再做精确计算。默认返回 100 行、最多 1000 行，保留 NULL、截断说明与结果有效期。结果及加密问句/分析载荷约 24 小时有效，幂等摘要和审计最多 90 天。

多轮追问需提交 `conversation_id` 及最新 `expected_revision`；新会话版本为 0。需要澄清时任务返回 `needs_clarification`，接入方显示 `clarification` 并让用户补充问题，必要时提交 `entity_choices` 中的服务端选项 ID。澄清不会自动执行 SQL。

轮询建议 1–5 秒退避；不要对历史所有结果高频刷新。收到 429 遵循 `Retry-After`。提交超时后必须使用原 `Idempotency-Key` 与相同输入重试；同键改输入返回 409。结果过期后原键不创建新任务，重新查询使用新键。

任务阶段包括 `queued/planning/querying/analyzing/succeeded`，以及 `needs_clarification/failed/cancelling/cancelled/cleanup_pending/expired`。SQL 取消未确认时不能将 `cancelling` 当作已停止；`cleanup_pending` 继续沿用原有源库人工清理确认流程。

任务总处理期限为 5 分钟；SQL 预算/排队期限和模型自身超时另行生效。分析失败时成功的表格仍可获取，检查 `analysis_status`。新建分析子任务不会重新运行 SQL。规划或分析进程中断且模型调用结果不确定时不自动重新发起付费调用。

错误统一返回 `code/message/request_id/retryable`，响应头同时带 `X-Request-ID`。生产反向代理还应对未认证令牌/票据端点配置入口频率限制；应用请求额度在认证成功后生效。

## 4. 代表用户调用

由受信任的业务后端/身份服务持有 RSA 私钥，在 LightSQL 应用配置中登记对应公钥和 `assertion_issuer`。只接受 RS256、至少 2048 位 RSA；声明最长有效期 120 秒。

声明字段：

```json
{
  "iss": "<登记的签发方>",
  "aud": "lightsql-integration",
  "sub": "<已映射的外部用户标识>",
  "client_id": "<当前应用 UUID>",
  "iat": 0,
  "exp": 0,
  "jti": "<每次声明唯一 UUID>"
}
```

`iat/exp` 用实际 UTC Unix 秒，`exp` 最多为 `iat+120`。将签名后的 JWT 通过令牌请求的 `subject_assertion` 字段提交；同一声明 jti 只能使用一次。应用密钥认证和用户身份声明同时校验，正文不能任意指定内部 user_id、tenant_id、角色或行权限。

业务后端必须先验证自身用户会话，再签发该用户的声明；不可把浏览器传来的任意 subject 直接签名。当前不自动同步企业组织/账号，也不自动识别各厂商 SSO 协议；需要按实际身份平台实现这一小段适配。

## 5. 嵌入问数界面

宿主页面引入 SDK：

```html
<div id="ask-panel" style="height:720px"></div>
<script src="https://lightsql.example.com/lightsql-embed.js"></script>
<script>
const widget = LightSQL.mount({
  container: document.querySelector('#ask-panel'),
  baseUrl: 'https://lightsql.example.com',
  clientId: '<公开应用 UUID>',
  topicId: '<固定主题 UUID>',
  title: '经营问数',
  welcome: '可以查询你负责的业务数据。',
  theme: 'light',
  getTicket: async (body) => {
    // 此 URL 由宿主后端实现：校验登录与 CSRF，使用后端令牌申请票据。
    const response = await fetch('/lightsql/ticket', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(body)
    });
    if (!response.ok) throw new Error('无法建立问数会话');
    return response.json();
  },
  revokeSessions: async () => {
    // 宿主后端以当前用户的应用令牌调用 DELETE /embed/sessions。
    const response = await fetch('/lightsql/logout', { method: 'POST' });
    if (!response.ok) throw new Error('尚未确认退出问数');
  },
  onError: error => console.error(error.message)
});
// 可置入页面面板、右侧抽屉或浮窗容器：
// widget.open(); widget.close(); widget.setContext({question:'预填问题'});
// 退出或切换用户时先 await widget.destroy()，再为新用户重新 mount。
</script>
```

SDK 不接受应用密钥。`getTicket` 收到 `{origin, challenge, topic_id}`，宿主后端核验登录身份和允许来源/主题后，携带该主体的应用令牌调用 `POST /embed/tickets`，将 `{ticket, expires_in}` 返回给 SDK。固定主题最终由服务端票据/会话限制。

iframe 通过 `POST /embed/sessions` 原子消费票据，获取受限会话令牌。父子消息双向检查 origin、窗口引用、协议版本和实例 ID；SDK 只传样式/预填问题及任务事件，不自动把查询行数据交给宿主。

会话令牌 15 分钟有效，SDK 在到期前请求新票据。宿主退出时应先阻止旧登录继续申请票据，再调用 `DELETE /embed/sessions` 撤销当前应用/主体的所有嵌入会话及未消费票据，最后销毁 iframe。批量撤销用于覆盖页面刷新和令牌续期前产生的旧会话；只有后端应用令牌可调用。单会话撤销接口为 `DELETE /embed/sessions/{id}`。

跨站登录不依赖第三方 Cookie。宿主浏览器需要能访问 LightSQL 域名，宿主 CSP 需要允许相应 `frame-src` 和 SDK 的 `script-src`。LightSQL 的嵌入页面通过响应头限定 `frame-ancestors`；管理页面默认只允许同源嵌入。反向代理不要额外附加冲突的 `X-Frame-Options: DENY/SAMEORIGIN` 到嵌入入口。

首期 SDK sandbox 仅开放脚本、保留 LightSQL 源和表单提交，不开放顶层导航和弹窗。图表与表格复用当前 LightSQL 渲染逻辑；默认问题只预填，不因页面加载而自动执行。

## 本版边界

- 正式业务系统的域名、身份映射和用户会话适配待实际接入方提供后联调。
- 未进行新的外部付费模型质量测试；浏览器中的模型是固定回放。
- 生产目标负载、长时间运行、TLS/网关配置及企业 SSO 兼容性需按目标环境验收。
- 当前使用轮询，未增加对外 SSE、Webhook、通用 SQL 直传、跨源 JOIN 或批量导出。
- 企业身份声明采用登记公钥的最小适配协议；不包含完整 OIDC 登录平台和组织同步。
- 密钥轮换立即失效，未实现双密钥宽限期。成员授权仍受当前主题策略最多 200 条成员记录的边界约束。
- 对外结果已被业务系统读取后，LightSQL 无法远程收回其副本，接入方应实施自身的数据访问与留存控制。

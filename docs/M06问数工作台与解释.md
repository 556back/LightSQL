## 使用入口与验收

打开 [问数工作台](http://127.0.0.1:8000/ask)，沿用现有账号和模型配置。

1. 选择已发布主题、新建会话，输入“净销售额按客户区域分组”，观察接收问题、生成并校验计划、提交查询、返回结果的状态。
2. 展开“核对口径与来源”，核对责任人、时区、语义版本、固定过滤和来源。管理员还可看到物理表名及现有执行 SQL；成员仅看到逻辑来源。
3. 在结果表格与图表中核对数字，按需调用现有结果分析。自由探索查询明确提示不自动套用标准指标的固定口径。
4. 点击“评价回答”，选择“结果有问题”、问题分类，填写说明并保存；重新打开可修改反馈。
5. 用左侧搜索框搜索问题或反馈说明。刷新当前页面，应恢复原会话、反馈和未过期的查询结果。
6. 网络暂时断开后恢复，进度流自动重新连接并读取最新状态；不会因为重连而重新调用模型或执行 SQL。

## 本次实现

| 能力 | 实际行为 |
|---|---|
| 流式进度 | Bearer 鉴权的 fetch SSE；持久化状态变化后发送完整快照，显示真实阶段与任务状态 |
| 断线恢复 | 自动重连并重新鉴权，恢复会话与查询任务的最新快照；URL 保存主题和会话位置 |
| 来源解释 | 编译器返回实际引用的数据模型，包含关联中间模型；CTE 名称不会被误当成业务来源 |
| 口径解释 | 使用已发布定义，显示指标说明/单位、固定过滤、语义/目录版本、责任人、时区和权限范围 |
| 时间解释 | 分别显示口径发布时间和查询完成时间；业务数据更新水位尚未接入，明确标注未知 |
| 历史 | 最多 100 个有效会话，按主题查看、按问题或反馈说明搜索，展示创建时间和反馈标记 |
| 反馈 | 有帮助/结果有问题，指标、筛选、数据、图表、其他分类；可更新，保存在现有加密轮次载荷中 |
| 并发保存 | 反馈与结果分析写入使用同一短事务锁，读取最新载荷后合并，避免互相覆盖 |
| 访问控制 | 会话归属、账号有效性、语义版本及授权变更持续复核；拒绝访问时隐藏当前会话并清理结果缓存 |

复用现有表格、柱状图、折线图、事实引用分析、查询取消、行数与字节限制。此次没有数据库结构迁移，也不需要修改现有模型密钥或数据源配置。


## 当前边界

- SSE 传递每秒读取的最新状态快照，连接最长约 25 秒后重连；事件 ID 是快照摘要。可恢复最终和当前状态，不实现规划中所述的完整逐阶段事件日志或 `Last-Event-ID` 历史补放，不输出模型思维链或伪造进度百分比。
- 问题、计划及反馈沿用 **24 小时**会话周期，到期清理加密内容；查询结果另受其有效期限制。当前反馈用于会话内核对，不自动发布到语义层。长期反馈队列、管理员审核及关联评测集在 M07 继续建设。
- 来源记录使用绑定的发布版本；若当前语义、目录绑定或授权变化使会话失效，旧内容不再展示，需新建会话。
- 模块回归有一条已存在的 Starlette/httpx 测试客户端弃用提示，不影响结果。M06 的浏览器实库验证使用 PostgreSQL；MySQL/Oracle 继续依赖已有三库回归，不宣称此次做了新的三库浏览器实测。

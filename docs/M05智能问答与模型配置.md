## 2. 可配置的模型服务

| 服务 | 预置基础地址 | 配置说明 |
|---|---|---|
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | 模型 ID 自行填写；JSON 模式及 thinking 可选 |
| DeepSeek | `https://api.deepseek.com` | 不硬编码模型型号；JSON 模式及 thinking 可选 |
| 千问 / 百炼北京 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | Key 必须匹配地域；思考开关映射为 enable_thinking |
| 千问 / 百炼新加坡 | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` | 根据账号地域选择地址 |
| 千问 / 百炼美国 | `https://dashscope-us.aliyuncs.com/compatible-mode/v1` | 根据账号地域选择地址 |
| 自定义兼容接口 | 部署端允许的 HTTPS 地址 | 兼容 Chat Completions、Bearer 认证与 message.content 响应 |

每个配置保存名称、厂商、地址、模型、密钥、5–90 秒超时、256–16384 输出 tokens、JSON 模式和思考模式。最多保存 30 个配置，通过独立启用操作切换当前模型。模型名称不使用过时的固定下拉枚举，由管理员按账号实际可用模型填写。思考模式默认不发参数，显式启用或关闭前需核对模型能力。

密钥使用现有 `DATASOURCE_ENCRYPTION_KEY` 加密体系保存，不回显。修改同一服务时留空保留密钥；修改厂商或地址必须重新输入，避免把原密钥发送到新地址。配置修改使用 revision 防止覆盖，增改、启停、删除和测试结果记录在 `gatewayaudit`；不记录密钥或供应商错误正文。删除 API 只允许删除非启用配置。

测试按钮只发送固定 JSON 测试内容，会产生一次真实模型请求；连接测试成功不证明业务问答正确。保存与启用本身不会调用模型。不自动故障转移到其他厂商，不自动发现模型，也不传递任意额外请求参数。

模型网关使用统一 Chat Completions 兼容协议，默认 `response_format=json_object`；仅保证要求 JSON，仍执行本地 Schema 校验。关闭 JSON 模式后只通过提示词要求 JSON，本地校验保持不变。响应必须完整结束，拒绝空内容、截断、refusal 和超过 256 KB 的响应。单次请求有整体超时，无网络自动重试、重定向或代理环境变量继承。

协议依据：智谱的[OpenAI 兼容说明](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)、DeepSeek 的[JSON 输出说明](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)、千问的[兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)及[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。JSON 模式与严格 Schema 输出的区别见 [OpenAI 官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)。以上是协议参考，不替代具体账号和模型的实测。

## 3. 问答流程与边界

1. 服务端绑定当前用户、发布版本、授权目录和 M04 查询策略。只有同时具备查询授权和外发许可的指标、维度进入模型上下文。
2. 在本地按已发布名称、别名和实体词典匹配问题，精确命中的指标优先排列；保留全部可外发且已授权的候选，不使用外部 embedding，也不静默截断候选目录。
3. 实体名称与编码转换为本轮 `value_N` 引用，模型只看引用及所属维度。实体歧义先在本地返回选项，选择值必须与本轮问题匹配。
4. 问题的未匹配片段必须属于本地通用问数词汇、标点或日期/普通数值。未知词语和长数字编码直接拦截；不会先调用外部模型做脱敏。日期与普通数值作为问数条件保留。
5. 模型只输出 `plan`、`clarify` 或 `unsupported` 的结构化决策。计划不包含 SQL、数据源、角色或行授权字段。过滤实体引用必须来自本轮本地映射，且与过滤维度一致。
6. 本地编译验证指标、维度、类型、关联和权限。结构/语义失败最多修复一次；修复请求不包含物理 SQL、驱动错误、原始模型响应或敏感值。网络失败、限流、空响应和截断直接结束，不自动重试。
7. 用户核对计划后，通过固定轮次 ID 幂等提交到 M04 查询队列。只有最新有效轮次可以首次执行；请求重放不产生重复查询任务。结果与取消继续使用 M04 的鉴权、限额、超时、审计和源库清理机制。

本地词汇允许名单是当前明确限制：自然语言表达尚不能保证广泛覆盖，未收录的正常用语也可能被拦截。需要结合真实题集扩充词汇与本地解析；不宣称通用敏感信息识别或脱敏无损。管理员对主题和字段的外发许可仍需逐项审核；批准的描述本身会外发。

## 4. 会话、追问与运行状态

- 会话绑定用户、主题发布版本和策略摘要，跨用户不可访问；语义重发、授权变化或账号停用后无法继续读取和执行。
- 追问将最近有效计划转换为带本轮实体引用的逻辑上下文，不发送原始历史问题、实体编码、SQL 或结果表。新问题要求生成完整计划；通过“清除上下文，独立提问”明确丢弃继承状态。
- 对澄清回复，在本地合并问题后重新执行完整出口检查。不会把未经检查的补充内容直接追加给模型。
- 会话与问题持久化，同一请求 ID 不能替换问题；并发修改通过 expected_revision 拒绝。每人同时最多 1 个模型规划，全局最多 4 个；每会话最多 50 轮，每人最多 100 个未过期会话。
- 原始问题、展开后的问题、计划和实体选项加密保存，24 小时后不可访问。查询 Worker 或会话接口触发清除；会话元信息 90 天后删除。模型配置审计当前不自动清除。
- 模型规划同步等待有限请求，界面通过轮询恢复状态，不是独立模型 Worker。规划进程异常后不自动重放付费请求；超过 4 分钟的 planning 状态标记失败，用户重新提问。
- 各轮保留配置 ID/revision、模型、次数、耗时和服务返回的 token 用量；当前未实现价格表、费用估算或模型质量评分。

M06 的 SSE、图表、综合解释、反馈等尚未开始。M05 提供计划核对和真实结果表格，不生成未经结果支持的经营结论。复杂时间比较、跨源 JOIN、任意表达式和超出 M04 能力的计划应澄清或拒绝；具体模型是否正确识别这些边界仍需真实题集验证。

## 6. 复现

从项目根目录执行，沿用 `.local/demo.json` 和已存在的合成数据库，不需要新建源业务数据：

```powershell
.venv/Scripts/python.exe scripts/module1_demo.py migrate
.venv/Scripts/python.exe scripts/module5_demo.py seed
.venv/Scripts/python.exe scripts/module1_demo.py openapi
Push-Location frontend
node ../node_modules/@hey-api/openapi-ts/bin/run.js
$env:VITE_API_URL='/'
node ../node_modules/vite/bin/vite.js build
node ../node_modules/typescript/bin/tsc -p tsconfig.build.json
Pop-Location
# 两个终端分别运行；先检查是否已有进程在监听
.venv/Scripts/python.exe scripts/module1_demo.py api
.venv/Scripts/python.exe scripts/module1_demo.py query-worker
.venv/Scripts/python.exe scripts/module1_demo.py test
```

独立回放验收（另一个终端运行浏览器脚本）：

```powershell
.venv/Scripts/python.exe scripts/module5_demo.py fixture-api
node scripts/module5_browser.cjs
```

回放 API 仅监听 `127.0.0.1:8005`，每次启动创建独立 `.local/module5-fixture-<UUID>.db` 元数据库副本，读取的源数据仍是本任务的合成库；模型配置和会话修改不影响主服务。完成后关闭回放服务；正常产品入口为 8000，默认没有启用模型。不要把回放入口当作真实模型运行环境。

自定义服务在部署环境增加：

```dotenv
MODEL_GATEWAY_ALLOWED_BASE_URLS=["https://model.internal.example/v1"]
```

Compose 已传递此配置。只接受精确匹配的 HTTPS 基础地址，不跟随跳转，不接受 URL 内用户名、密码、查询参数或片段。当前自定义协议仅支持 Bearer Key，不覆盖 Azure 专有认证、Anthropic 原生协议、厂商应用工作流接口或 HTTP 内部模型服务。

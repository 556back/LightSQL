# LightSQL 运维手册

适用当前模块化单体：FastAPI API、目录 Worker、查询 Worker、PostgreSQL 元数据库；业务查询支持 PostgreSQL、MySQL、Oracle。更新时间：2026-09-07。

## 部署与发布

1. 为正式环境建立独立 `.env`，配置 `PROJECT_NAME`、`DATABASE_URL`（非 Compose 启动时）、`POSTGRES_PASSWORD`（Compose）、`SECRET_KEY`、初始管理员及其独立密码。不要复用 `.local/demo.json` 或固定演示账号。
2. 所有 API 和 Worker 使用同一 `DATASOURCE_ENCRYPTION_KEY`。主密钥用独立秘密管理系统保管，不能只备份数据库；直接更换主密钥会使旧凭证、模型密钥、问答和质量记录无法解密。
3. 配置显式 `DATASOURCE_ALLOWED_HOSTS`，自定义模型地址配置 `MODEL_GATEWAY_ALLOWED_BASE_URLS`，同时控制部署环境 DNS/出口。为三库配置专用只读账号及所需 CA。现有公开注册默认关闭，Compose 显式固定为 false。
4. 前端同源构建使用 `VITE_API_URL=/` 或空字符串，避免把本机开发 API 地址编译进交付文件。仅采用已有 lockfile 的依赖；生产发布前固定已验证镜像摘要并保留上一个版本。
5. 在有真实环境变量的部署终端验证 Compose 配置，构建镜像并启动。显式传 `-f` 不会加载仅供开发的 override。`prestart` 先执行迁移和初始化，成功后 API 才可启动，Worker 等 API 健康后启动。

```powershell
docker compose -f compose.yml -f compose.deploy.yml config --quiet
docker compose -f compose.yml -f compose.deploy.yml build backend
docker compose -f compose.yml -f compose.deploy.yml up -d
docker compose -f compose.yml -f compose.deploy.yml ps
```

现有 deploy 文件使用 Traefik 和公网证书挑战；纯内网应由部署方配置实际可用的内部证书入口或内部反向代理，不应假设公网 ACME 在隔离内网可用。管理库工具 Adminer 只应暴露在受控管理网络。API 健康检查是应用存活检查，不代替质量页的 Worker 与备份检查。SSE 代理需关闭缓冲并允许至少 30 秒读取时间；应用响应已设置 `X-Accel-Buffering: no`。

本轮验证了本地运行、迁移和 Compose 结构；没有在未知生产网络执行以上部署命令，也未验证目标生产证书或镜像构建。

## 日常巡检与故障定位

| 项目 | 检查和操作 |
|---|---|
| Worker 心跳 | 质量页超过 35 秒告警时检查相应进程及元数据库连通性。心跳线程证明进程仍可访问元库，不证明每项业务工作成功 |
| 队列等待 | 查询队列默认满 30 秒过期；目录队列超过 60 秒需检查 Worker。查询全局最多 5 项、每源 2 项、每人 1 项，多个实例共享元数据库额度；心跳不代表生产容量已验收 |
| `cleanup_pending` | 源库取消/清理尚未确认，系统会暂停该源新查询；先由管理员/DBA 核对目标库会话是否确实结束。不得直接将任务改成成功或循环重试以隐藏状态 |
| 模型失败 | 核对模型设置的连接测试、模型名称、地址白名单、超时与服务侧限额，再查看问答阶段及脱敏错误。不要把原始密码、API key 或完整查询结果复制进日志 |
| 反馈 | 审核指标口径、筛选、数据或图表原因。确认修复后加入同主题回归题并关联，语义修改另经原有草稿/发布流程核对，可恢复以前版本 |
| 备份 | 每日创建新归档，检查大小、摘要和成功记录；保存到另一故障域。每月和重大迁移前在隔离环境演练恢复，核对独立密钥 |
| 磁盘 | 页面显示 API 所在文件系统的可用空间，不代表元数据库盘或业务源库盘；这些盘需宿主平台单独监控 |
| 用量 | 页面 Token 仅包括已记录的问答规划用量，不含分析、连接测试及供应商其他计费；账单应以实际模型服务商记录为准 |

日志入口：Compose 使用 `docker compose ... logs --tail 100 backend catalog-worker query-worker prestart`；本地演示使用 `.local/api.err.log`、`.local/worker.err.log`、`.local/query-worker.err.log`。查看日志只提取诊断信息，不发布包含凭证或业务正文的原始日志。

监控告警目前在质量页展示，无外部通知投递。正式平台可根据心跳、队列、清理未确认、磁盘和备份时效配置持续异常通知。每日备份的定时执行由运维平台/系统任务计划部署；本模块交付脚本，不在用户机器静默创建定时作业。

## 一致性备份与恢复演练

`scripts/metadata_backup.py` 在维护主机运行，需要项目 Python 依赖、Docker CLI/对应容器访问权，以及能访问元数据库的 `DATABASE_URL`。Compose 私有网络中的 `db` 名称通常不能由宿主解析，维护主机应使用受控管理网络地址或已经配置的隧道，不为执行脚本临时公开数据库。该工具目前要求 PostgreSQL 管理权限读取系统标识并导出快照，执行人员需有相应维护权限。

工具只备份 `public` 元数据 schema，业务源库内容不在恢复范围。归档可能含用户邮箱、密码哈希、语义定义和业务配置；应存储在受控加密目录并限制读取。密钥分开保管，不放进归档旁的 JSON。SHA-256 用于检测文件损坏，不是可信签名，归档和清单都应来自受控备份源。

```powershell
# 演示环境：使用明确的本地合成容器。文件必须是新名称，不覆盖旧备份。
.venv/Scripts/python.exe scripts/metadata_backup.py backup --demo --container lightsql-module-demo-postgres-1 --file .local/backups/metadata-new.dump
.venv/Scripts/python.exe scripts/metadata_backup.py restore-test --demo --container lightsql-module-demo-postgres-1 --file .local/backups/metadata-new.dump
```

正式环境去掉 `--demo` 并指定真实维护容器；工具从已配置的应用环境读取数据库和主密钥。备份先比对应用数据库和容器的 PostgreSQL 系统标识，以防连接错集群。恢复会创建 `lightsql_restore_<随机值>`，拒绝指定既有目标库；只在这个刚创建的新库中移除空 public schema，再恢复归档。不会自动启动 API/Worker、发起模型调用或连接恢复出来的业务数据源。

成功后输出 `.dump.json` 和 `.dump.restore.json`，分别包含快照表行数、摘要和恢复证据。恢复检查表集合与每表行数，并尝试解密所有非空数据源密码、模型密钥及加密载荷，不打印解密明文。缺少或错误主密钥时不得将恢复认定为成功。

测试库保留供复核。结束后先检查恢复证据中的**完整数据库名**与 Docker 容器，确认属于本次恢复且没有连接业务服务，再由维护者删除该测试库。失败时可能留下空/部分新库；不会清理或覆盖原库。恢复库包含元数据及加密凭证，适用与备份相同的访问保护。

当前演练是单机小型数据集，不验证异地存储、灾难情况下的主机重建、生产规模吞吐或正式目标 RPO ≤24 小时/RTO ≤4 小时。恢复正式服务时，先在隔离网络验证版本、密钥与权限，再由发布负责人切换服务入口；不要让恢复库的 Worker 与原实例同时处理同一批持久任务。

并发参数、三库合成验证、默认预算下的突发超时证据和当前本地日志路径参见 [M07 三库回归与并发验证](M07三库回归与并发验证.md)。配置降低时统一修改所有 API/Worker；混用不同限额无法保证较小值。需要退回串行时，将 `QUERY_MAX_CONCURRENCY=1` 并在当前任务结束后重启查询 Worker。

## 变更回滚

发布前保留镜像、锁文件、迁移版本、当前语义发布版本与一致性备份。本次迁移仅新增 M07 表，但 `downgrade` 会删除质量历史，不能作为保留历史的通用回滚。应用可回到验证过的兼容镜像；语义可以恢复旧定义后重新发布。数据库结构优先前向修复；需要数据恢复时使用已演练归档和独立密钥，在新库验证后切换。

停机或替换本地演示服务前，核对 `.local/*.pid` 对应进程的命令与本项目路径。Windows Python 启动器可能另有子进程，应核对监听端口所属进程，避免停止其他 Python 服务。

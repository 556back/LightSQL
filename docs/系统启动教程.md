# LightSQL 完整启动教程

适用版本：2026-09-08 仓库当前实现。以下命令在 Windows PowerShell 中执行，仓库位置以 `D:\Projects\LightSQL` 为例。

推荐先用方案 A 启动全新系统；继续使用本机已有演示数据请选择方案 B。两套环境数据库和密钥独立，不会自动互通。全新启动不会自动创建业务数据、主题或模型密钥。

## 一、先理解需要启动什么

| 服务 | 作用 | 未启动时的现象 |
| --- | --- | --- |
| PostgreSQL 元数据库 | 用户、目录、主题、权限、任务和加密配置 | API 无法正常工作 |
| prestart | 升级数据库结构，创建首个管理员；执行完退出 | 缺表、无法登录 |
| backend | 管理页面、问数页面和 API；镜像内包含前端 | 无法打开系统 |
| catalog-worker | 同步业务库表与字段目录 | 目录同步一直排队 |
| query-worker | 执行只读 SQL | 查询一直排队 |
| integration-worker | 编排外部 API 和嵌入问数任务 | 外部任务停在 queued / querying |

业务数据库与元数据库是不同用途。PostgreSQL、MySQL、Oracle 业务库按实际情况接入；系统不要求同时安装这三种业务库。模型也需要单独配置，结构化指标查询本身不依赖模型。

## 二、方案 A：全新系统，一次启动所有服务（推荐）

### 1. 准备环境

安装并启动支持 Linux 容器的 Docker Desktop，确认 Docker 引擎已运行。本方案不需要在 Windows 安装 Python、Bun 或 Node，依赖在镜像中安装。

```powershell
Set-Location D:\Projects\LightSQL
docker version
docker compose version
```

`docker version` 应同时显示 Client 和 Server。首次构建需要访问 Docker Hub、GHCR、npm 与 Python 包仓库；内网环境需提前准备镜像和依赖代理。Dockerfile 当前使用 Python 3.14、Bun 1；仓库 Python 依赖要求 `>=3.14`。

### 2. 生成独立配置

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\init-local-env.ps1
```

生成 `.local/startup.env`，其中包含随机管理员密码、元数据库密码、会话签名密钥和数据加密密钥。重复执行会保留已有文件，避免覆盖密钥。

初次生成时可指定邮箱和端口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\init-local-env.ps1 -AdminEmail admin@yourcompany.com -Port 18000
```

在本机编辑器打开配置：

```powershell
notepad .local\startup.env
```

默认管理员邮箱为 `admin@lightsql.example.com`，密码是文件中的 `FIRST_SUPERUSER_PASSWORD`。请妥善保存文件，不要提交或发送其内容。首次启动后的管理员密码应在系统内修改；修改环境变量不会重置已存在账号。

| 配置项 | 用途与填写方式 |
| --- | --- |
| `LIGHTSQL_PORT` | 本机访问端口，默认 18000 |
| `FIRST_SUPERUSER` / `FIRST_SUPERUSER_PASSWORD` | 仅初始化管理员时使用 |
| `POSTGRES_PASSWORD` | 元数据库密码；使用已有数据卷时不能只改此值 |
| `SECRET_KEY` | 登录和应用令牌签名，需长期保留 |
| `DATASOURCE_ENCRYPTION_KEY` | 加密数据源密码、模型密钥及任务内容，必须与数据库一起备份 |
| `DATASOURCE_ALLOWED_HOSTS` | 允许接入的业务数据库主机，JSON 数组，如 `["10.0.0.20","db.internal"]` |
| `MODEL_GATEWAY_ALLOWED_BASE_URLS` | 自建或非预设模型接口白名单，JSON 数组；填精确 base URL |

容器内的 `127.0.0.1` 指容器自身。连接 Windows 宿主机上的业务库时，填写 `host.docker.internal`，并加入 `DATASOURCE_ALLOWED_HOSTS`。例如接本机已有演示库，可设置 `["host.docker.internal"]`，业务库端口使用宿主机映射的 15432 / 13306 / 11521，并确认数据库允许容器访问。跨机器数据库应使用真实内网主机地址。

### 3. 校验、构建、启动

始终显式使用下列 `--env-file` 和 `-f` 参数，避免默认开发 Compose 覆盖文件参与合并。

```powershell
docker compose --env-file .local/startup.env -f compose.local.yml config --quiet
docker compose --env-file .local/startup.env -f compose.local.yml build backend
docker compose --env-file .local/startup.env -f compose.local.yml up -d --wait --wait-timeout 180
```

逐条执行，上一条失败时先处理错误。首次构建可能较久。`prestart` 负责执行 `alembic upgrade head` 和初始化管理员，无需重复手工建表。此配置的项目名是 `lightsql-local`，元数据保存在独立的 `lightsql-local_metadata` 卷中。

### 4. 验证和登录

```powershell
docker compose --env-file .local/startup.env -f compose.local.yml ps -a
Invoke-RestMethod http://localhost:18000/api/v1/utils/health-check/
```

预期：db、backend 为 healthy，三个 Worker 为 Up，prestart 为 Exited (0)。健康接口返回 `true`。Worker 显示 Up 只证明进程存活，还要通过目录同步和真实查询确认端到端执行。

- 系统与登录：[http://localhost:18000](http://localhost:18000)
- 外部系统接入：[http://localhost:18000/integrations](http://localhost:18000/integrations)
- 内部 API 文档：[http://localhost:18000/docs](http://localhost:18000/docs)
- 对外 API 契约：[OpenAPI](http://localhost:18000/api/integration/v1/openapi.json)

如修改端口，上述地址需同步替换。本配置仅绑定本机回环地址；需要其他系统访问时，在部署机配置 HTTPS 反向代理和正式域名，再以正式地址登记嵌入来源。嵌入宿主来源是业务系统的地址，不是 LightSQL 自己的地址。

### 5. 首次业务配置：从登录到真正可问数

按以下顺序操作，避免空主题、空授权导致接入失败：

1. **用户管理**：创建并启用一个普通业务用户。管理员负责管理，外部应用的执行身份必须使用普通用户。
2. **数据源** `/datasources`：使用业务数据库只读账号登记连接，测试连通性并保存。账号需要读取所需表及相应元数据权限。
3. **数据目录** `/catalog`：发起同步，确认任务完成且能看到目标表和字段；失败时查看 catalog-worker 日志。
4. **业务主题** `/topics`：基于目录创建主题，配置模型关系、指标与维度，校验后发布版本；添加普通用户为主题成员。
5. **查询执行** `/queries`：为该普通用户配置指标、维度、行范围；自由探索还需要逐列授权。主题发布新版本后确认查询授权仍有效。先执行一条结构化查询并核对结果。
6. **模型配置** `/models`：自然语言问数需配置实际模型服务地址、模型名和 API Key，验证后启用。非预设接口先在环境白名单登记并重建服务。模型测试及问数可能消耗供应商额度。
7. **智能问数** `/ask`：以普通用户进入已授权主题，提交一个清晰问题，确认查询结果与来源。
8. **外部系统接入** `/integrations`：创建应用，选择权限上限用户、开放主题和能力；嵌入接入填写宿主来源。点击“检查接入配置”，处理所有提示后保存并保管一次性密钥。
9. 使用页面“后端 API 自检”示例验证认证及可见主题；需要执行查询、追问或嵌入时，继续按 [外部系统接入开发与使用](外部系统接入开发与使用.md) 完成宿主后端和票据接口。

配置检查不执行 SQL、不调用模型，也不替代 Worker 与数据库连通性验证。固定应用使用 `$app` 主体；个人身份接入须配置 RSA 公钥和外部用户映射，不能直接相信浏览器传来的用户 ID。

### 6. 日常启动、停止、日志和升级

```powershell
# 停止进程，保留容器和数据库
docker compose --env-file .local/startup.env -f compose.local.yml stop

# 再次启动；也适用于修改 startup.env 后使新环境配置生效
docker compose --env-file .local/startup.env -f compose.local.yml up -d --wait --wait-timeout 180

# 最近日志；加 -f 可持续跟踪，Ctrl+C 只退出日志查看
docker compose --env-file .local/startup.env -f compose.local.yml logs --tail 100 backend catalog-worker query-worker integration-worker

# 检查初始化失败原因
docker compose --env-file .local/startup.env -f compose.local.yml logs --tail 100 prestart
```

升级前按 [运维手册](M07运维手册.md) 备份元数据库和加密密钥。更新代码后，停服、构建，再由 prestart 迁移：

```powershell
docker compose --env-file .local/startup.env -f compose.local.yml stop
docker compose --env-file .local/startup.env -f compose.local.yml build backend
docker compose --env-file .local/startup.env -f compose.local.yml up -d --force-recreate --wait --wait-timeout 180
```

停止或升级不需要删除数据卷。不要使用 `down -v` 做日常重启，它会删除元数据库数据。生产恢复应同时恢复匹配的 `DATASOURCE_ENCRYPTION_KEY`；新生成密钥无法解密旧数据。

## 三、方案 B：继续使用当前电脑的已有演示环境

本仓库已有演示脚本配置 `.local/demo.json`，元数据库为 `127.0.0.1:15432/lightsql_demo`，管理入口为 8000。它与方案 A 的 `.local/startup.env` 无关。

### 1. 开发依赖

本地需要 Python 3.14、uv、Node 和 Bun；版本约束以 `backend/pyproject.toml`、`frontend/package.json`、锁文件为准。已存在可用 `.venv` 与 node_modules 时可跳过安装。

```powershell
Set-Location D:\Projects\LightSQL
uv sync --frozen --package app
bun install --frozen-lockfile
```

### 2. 启动演示数据库并准备初始数据

```powershell
.venv\Scripts\python.exe scripts/module1_demo.py prepare
docker compose --env-file .local/demo.env -f compose.demo.yml up -d postgres mysql
docker compose --env-file .local/demo.env -f compose.demo.yml ps
```

等待数据库就绪。MySQL 启动日志出现 ready for connections 后再执行 seed；如果库刚初始化而 seed 提示连接被拒绝，待就绪后重跑：

```powershell
docker compose --env-file .local/demo.env -f compose.demo.yml logs --tail 30 mysql
.venv\Scripts\python.exe scripts/module1_demo.py seed
```

seed 会迁移元数据库、创建管理员、两张合成订单表与只读账号。它不自动完成语义主题、查询授权和真实模型配置。已有演示环境仅升级结构可执行 `scripts/module1_demo.py migrate`，无需再次 seed。

### 3. 构建前端

```powershell
$env:VITE_API_URL='/'
Set-Location frontend
npm run build
Set-Location ..
```

产物写入 `backend/app/frontend`，由 API 同源提供页面。`VITE_API_URL=/` 避免将前端开发 `.env` 中固定 localhost 地址写入部署产物。

### 4. 分别在四个 PowerShell 终端启动

每个终端先进入 `D:\Projects\LightSQL`，各执行一条：

```powershell
# 终端 1：API 和页面
.venv\Scripts\python.exe scripts/module1_demo.py api
```

```powershell
# 终端 2：目录同步
.venv\Scripts\python.exe scripts/module1_demo.py worker
```

```powershell
# 终端 3：SQL 查询执行
.venv\Scripts\python.exe scripts/module1_demo.py query-worker
```

```powershell
# 终端 4：外部任务编排
.venv\Scripts\python.exe scripts/module1_demo.py integration-worker
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。演示初始账号为 `admin@lightsql.example.com`，初始密码 `LightSQL-Demo-2026!`；如已在系统修改，请用修改后的密码。这是固定演示凭证，不用于生产。

已有对应进程时不要重复启动，先确认端口或进程，再在原终端 Ctrl+C 重启。修改后端代码需重启 API 和相关 Worker；修改前端需重新构建并刷新浏览器。

前端开发热更新可另开终端运行 `cd frontend; npm run dev`，访问 5173；Vite 将 `/api` 代理到 8000。嵌入完整联调建议使用 8000 同源构建入口。

## 四、常见问题

| 现象 | 处理方法 |
| --- | --- |
| Docker 无 Server / 无法连接管道 | 启动 Docker Desktop，确认 Linux 容器引擎可用 |
| 镜像拉取失败或依赖下载超时 | 检查构建日志中的具体仓库地址与网络代理；不要跳过失败的构建直接启动 |
| 端口占用 | 方案 A 修改 `LIGHTSQL_PORT`；方案 B 检查现有 8000 服务，不重复启动 |
| prestart 非 0 退出 | 查看 prestart 日志，检查数据库凭据与迁移；已有卷的密码不会随环境变量自动改变 |
| 页面正常但所有接口失败 | 前端用 `VITE_API_URL=/` 重建；确认反向代理同时转发页面和 `/api` |
| 数据源主机被拒绝 | 把实际连接主机加入允许列表，保持 JSON 数组格式，并重建容器使环境生效 |
| 容器访问本机数据库失败 | 不填 localhost；使用宿主机地址并检查监听、防火墙和只读账号来源授权 |
| 解密失败 | API 和三个 Worker 必须使用同一加密密钥；恢复旧数据库时恢复原密钥 |
| 目录或外部任务一直排队 | 按第一节检查对应 Worker；仅 API 健康不代表完整执行链路健康 |
| 登录后没有主题 / API topics 为空 | 检查发布、主题成员、应用主题范围和查询授权，而非只检查登录账号 |
| 嵌入页面未授权 | 来源精确匹配协议、域名与端口；票据接口必须真实实现；票据一次性且 60 秒过期 |
| 应用修改后原令牌报 401 | 配置版本变化会撤销旧令牌，业务后端重新取令牌 |
| 旧任务结果无法读取 | 任务有过期时间且权限变更会使快照失效；重新授权后提交新任务 |

## 五、启动成功的验收清单

- 能登录管理界面，并打开 `/integrations`。
- API 健康检查返回 true，三个 Worker 持续运行。
- 至少一个只读数据源连接成功，目录同步完成。
- 已发布主题，普通用户具备成员资格与查询授权。
- 一条结构化查询成功；需自然语言能力时，真实模型问数成功。
- 外部应用配置检查通过，后端令牌与可见主题自检成功。
- 外部查询经历提交、处理、成功及结果读取；嵌入场景另验证票据授权和退出撤销。

真实模型、业务数据源和目标业务系统仍需配置后联调；仅启动容器不会自动接通这些外部服务。

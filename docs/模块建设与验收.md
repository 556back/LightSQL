## 3. M01 已实现的行为

### 3.1 页面与操作

- M01 交付时登录后进入数据源管理页；M03 起默认进入业务主题。数据源维护仍只对管理员开放。
- 显示数据源数量、最近测试正常数量、待检查数量；状态反映最近一次测试，并非实时健康监控。
- 按名称、地址、数据库搜索，按数据库类型筛选；展示空态、加载状态和失败重试。
- 新建 PostgreSQL/MySQL/Oracle/达梦/人大金仓连接，配置名称、主机、端口、数据库（Oracle 为 Service Name，达梦为默认 Schema）、账号、密码、TLS 和备注。
- 打开详情，查看配置、最近测试时间和失败原因；密码不可回显。
- 编辑时密码留空即保留原密码；修改实际连接参数后，旧测试结果自动失效。
- 测试连接、启用/停用、确认删除；删除只移除本系统中的连接配置。

### 3.2 后端与边界

| 项目 | 当前实现 |
|---|---|
| 管理权限 | 全部数据源 API 仅超级管理员可用；公开注册默认关闭 |
| 密码存储 | 独立 Fernet 密钥加密；接口和验证失败响应不返回密码或密文 |
| 目标主机 | 部署端显式主机允许名单；默认空名单拒绝连接 |
| 连接测试 | 短连接，仅执行固定 `SELECT 1` 或 `SELECT 1 FROM DUAL`，配合只读事务设置 |
| 超时 | 连接/驱动调用约 5 秒预算；DNS、网络栈和驱动可能使总耗时更长，不承诺硬性 5 秒截止 |
| TLS | 默认验证服务器证书；可信 CA 由部署环境配置。MySQL 最低 PyMySQL 1.2，防止静默降级。达梦证书校验尚未适配，选择 verify-full 时明确失败且不发起明文连接；目前仅适用于可信本地测试 |
| 并发修改 | 配置 revision + 行锁；旧版本编辑拒绝，测试期间配置变化时不写入旧测试成功状态 |
| 操作留痕 | 建立 DataSourceAudit，记录操作者、数据源 ID、动作、时间；删除配置后记录仍保留 |
| 迁移 | Alembic 新增 datasource、datasourceaudit；保留模板既有用户和业务表 |

**连接成功只证明认证与基础读取可用，不证明账号只有只读权限，也不证明所有目标业务表均可读取。** 正式连接应使用 DBA 配置的专用只读账号与授权视图；元数据和查询能力在后续模块验收。

### 4.1 建议验收顺序

1. 登录，检查数据源卡片、列表和品牌布局；当前有五个真实演示库。
2. 输入“销售”搜索，筛选 MySQL；清空搜索并切回全部类型。
3. 对五个演示库分别点击“测试”，应成功并更新最近测试时间。
4. 打开连接详情，确认密码不可查看，TLS、主机、数据库和备注清晰。
5. 编辑一个演示库的备注，密码留空保存，再次测试应继续成功。
6. 停用一个演示连接，确认测试按钮不可用；再启用并测试。
7. 新建一次性测试配置，使用 `127.0.0.1` 和未占用端口，输入虚构密码；应能保存配置，测试后显示失败原因而不泄漏密码。
8. 删除该一次性配置，确认列表和统计数量更新；已有业务数据库内容不受影响。
9. 查看 Oracle 的 Service Name、达梦的默认 Schema、金仓的 PG 模式提示和各自默认端口；达梦开启 TLS 校验时应明确拒绝连接。

### 4.2 复现环境（PowerShell）

前提：Python 3.14/uv、Node.js、Docker Desktop 可用。以下命令从项目根目录执行。Bun 未全局安装时，使用 npm 临时运行；不要把 .local 中的密钥提交到仓库。

```powershell
uv sync --all-packages --group dev
.venv/Scripts/python.exe scripts/module1_demo.py prepare
docker compose --env-file .local/demo.env -f compose.demo.yml up -d
# 等待 PostgreSQL 与 MySQL 接受连接后执行 seed；Oracle 首次启动需数分钟。
.venv/Scripts/python.exe scripts/module1_demo.py seed
.venv/Scripts/python.exe scripts/extended_databases.py oracle
# 国产库下载、启动与初始化步骤见《数据库扩展验证记录》。
.venv/Scripts/python.exe scripts/module1_demo.py openapi
Push-Location frontend
npm exec --yes --package=bun -- bun install --frozen-lockfile
npm exec --yes --package=bun -- bun run generate-client
$env:VITE_API_URL='/'
npm exec --yes --package=bun -- bun run build
Pop-Location
.venv/Scripts/python.exe scripts/module1_demo.py api
```

演示数据库全部绑定 `127.0.0.1`，端口为 PostgreSQL 15432、MySQL 13306、Oracle 11521、达梦 15236、金仓 15421，使用独立命名卷。服务启动脚本生成并复用 `.local/demo.json` 的随机数据库密码、JWT 密钥和数据源加密密钥，覆盖演示关键连接配置，并关闭发信与公开注册；不会修改根目录 `.env`。

结束演示时在运行 API 的终端按 Ctrl+C，再运行以下命令停止演示数据库。保留命名卷以便下次继续验收：

```powershell
docker compose --env-file .local/demo.env -f compose.demo.yml --profile extended stop
```

本次代理以隐藏进程启动 API，进程记录位于 `.local/api.pid`，日志位于 `.local/api.log` 与 `.local/api.err.log`。如需重启，先核对进程命令属于 `scripts/module1_demo.py api`，再停止对应进程，避免影响其他本地服务。

### 4.3 正式环境的最小配置

- `DATASOURCE_ENCRYPTION_KEY`：单独生成 Fernet 密钥，与数据库备份分开保管；所有 API/Worker 使用同一受控密钥。不能简单替换密钥，否则旧凭证无法解密；轮换需另行迁移重加密。
- `DATASOURCE_ALLOWED_HOSTS`：JSON 数组，例如 `["analytics.internal","oracle.internal"]`；只配置受控数据库主机，DNS 与网络出口也应由部署环境管理。
- `ENABLE_PUBLIC_SIGNUP=false`：内部账号由管理员开通。
- 默认使用 TLS 验证；当前自定义 CA 通过主机/容器信任库部署，未实现网页上传 CA/Wallet。
- 生产使用独立凭证与正式元数据库；演示脚本和固定演示管理员密码不用于生产。

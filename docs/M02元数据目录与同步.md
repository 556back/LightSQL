入口：[元数据目录](http://127.0.0.1:8000/catalog)。账号 `admin@lightsql.example.com`，密码 `LightSQL-Demo-2026!`，仅用于独立合成演示环境。

| 能力 | 实际行为 |
|---|---|
| 选择数据源 | 五库切换，停用的数据源隐藏目录并禁止同步 |
| 配置范围 | 先选 Schema，再明确勾选表/视图；跨 Schema 累积选择、搜索、移除与清空；单源最多 200 个对象 |
| 默认边界 | 初始范围为空；新建业务表不会自动进入目录；无任意 SQL、通配符或业务行预览入口 |
| 目录 | 原生字段类型、顺序、可空性、中文注释、主键、表/视图类型、目录版本及最后同步时间 |
| 关系 | 按约束分组的外键，保留复合字段配对顺序；只显示当前范围中两端均存在的关联 |
| 搜索 | 表名、Schema、字段名、注释联合搜索；表/视图筛选；表内字段搜索 |
| 同步 | API 返回 202 与任务 ID；独立 Worker 读取系统目录；网页自动更新状态和目录 |
| 差异 | 对象新增/移出、字段新增/移除/定义变化、注释、类型、主键和关联变化；显示变更前后内容 |
| 历史 | 持久保存任务、操作者、开始/结束、范围版本、目录版本及差异；页面显示最近 20 次 |
| 错误与提示 | 连接错误脱敏；失败保留原快照；缺失的键元数据有明确提示，不推断未知关联 |

同步仅执行固定的系统目录查询，不采样业务记录，不发送模型请求。视图当前只采集输出字段，不解析视图 SQL 或血缘；索引优化信息、枚举取值、分区详情、同义词和物化视图不在本模块范围内。

## 2. 范围与一致性

- 全部 M02 API 仅超级管理员可用。这里的范围是数据源目录范围，业务用户的主题与行列权限由后续模块建设。
- 保存范围时校验数据源 revision 和范围 revision，拒绝过期编辑；移出的表及相关关联立即从当前目录隐藏。
- 数据源发生任何配置编辑后，先隐藏旧目录并要求重新确认范围。当前采取保守策略，备注修改也会触发确认。重新确认会清空旧连接快照，避免混用不同数据库的结构。
- 同步时复制配置与范围、释放元数据库事务后连接业务库；发布前重新核对启用状态及两类 revision。中途停用、删除或修改配置/范围，旧任务结果作废。
- 新快照与差异在同一事务内发布。连接、驱动或字典查询异常时，不把部分结果当作完整目录覆盖旧快照。
- 系统目录查询成功但对象已不可见时，记录为“移出”，含删除、权限撤销或范围调整，不声称已经区分物理删除与撤权。
- 历史差异仅管理员可查，保留历史对象标识；不会作为当前授权目录提供给问数。
- 每个源的同版本重复提交返回现有活动任务；源行锁保证提交串行。元数据库使用 PostgreSQL 的 `FOR UPDATE SKIP LOCKED` 领取队列任务。
- 运行任务租约 90 秒，逐对象续租；租约令牌及截止时间检查防止过期 Worker 回写。超时任务标记失败，用户可重新同步；排队任务跨 API/Worker 重启保留。不自动重试失效任务。
- 单连接/单驱动读取约 5 秒预算；同步总时长与对象数量相关，不承诺硬截止。当前按需手动提交同步，未启用定时扫描。

## 3. 五库实测矩阵

每库准备 `m02_customers`、`m02_orders`、`m02_order_summary`（Oracle/达梦为大写名称），共 2 表、1 视图、9 字段。只读账号沿用 M01，没有给业务账号添加写权限。新表不含业务行。

| 数据库 | Schema | 字段/注释/主键/视图 | 复合外键 |
|---|---|---|---|
| PostgreSQL 18 | demo_sales | 通过 | tenant_id、customer_id 与目标同序配对，通过 |
| MySQL 8.4 | sales_demo | 通过 | 同上，通过 |
| Oracle 26ai Free | LIGHT_DEMO | 通过 | 同上，通过 |
| KingbaseES V9 PG 模式 | light_demo | 通过 | 同上，通过 |
| 达梦 DM8 | LIGHT_DEMO | 通过；主键由 ALL_CONSTRAINTS + ALL_IND_COLUMNS 补齐 | **当前只读账号受限**，已发现约束但未取得字段映射，页面与快照明确提示 |

### 达梦边界

实测 `ALL_CONSTRAINTS` 返回主外键，`ALL_IND_COLUMNS` 返回授权表的索引列，但 `ALL_CONS_COLUMNS` 对 `LIGHT_READER` 返回空集；同一查询在本地 DBA 账号下有结果。原生 `SYS.SYSCONS` / `SYS.SYSINDEXES` 对只读账号拒绝读取。

当前连接器通过明确的约束索引补齐主键，**不根据相似字段名或普通索引猜测外键配对**。在目录的完整性提示被解决前，这些外键不得用于后续自动关联。正式库需 DBA 核实该版本的字典可见性，或提供受控元数据视图后再补适配与实测。本模块没有授予全库字典权限，也未将 DBA 凭证配置到应用连接器。

此边界与 M01 连接成功不矛盾，达梦 TLS 校验、国产库试用许可与目标版本限制仍按[数据库扩展验证记录](数据库扩展验证记录.md)执行。

实现参考：[PostgreSQL pg_constraint](https://www.postgresql.org/docs/current/catalog-pg-constraint.html)、[Oracle ALL_TAB_COLUMNS](https://docs.oracle.com/en/database/oracle/oracle-database/26/refrn/ALL_TAB_COLUMNS.html)、[达梦系统函数附录](https://eco.dameng.com/document/dm/zh-cn/pm/sql-appendix)。上述支持结论以本节真实只读账号测试为准。

## 4. 运行与复现

从项目根目录执行，沿用已准备的 `.local/demo.json` 和五个独立 Docker 数据库：

```powershell
# 更新元数据库；保留既有用户、数据源和业务表。
.venv/Scripts/python.exe scripts/module1_demo.py migrate

# 准备本模块的合成结构（幂等，不注册/覆盖生产连接）。
.venv/Scripts/python.exe scripts/module2_demo.py seed

# 更新前端契约并构建。
.venv/Scripts/python.exe scripts/module1_demo.py openapi
Push-Location frontend
node ../node_modules/@hey-api/openapi-ts/bin/run.js
$env:VITE_API_URL='/'
node ../node_modules/typescript/bin/tsc -p tsconfig.build.json
node ../node_modules/vite/bin/vite.js build
Pop-Location

# 分别在两个终端运行，或用现有隐藏进程。
.venv/Scripts/python.exe scripts/module1_demo.py api
.venv/Scripts/python.exe scripts/module1_demo.py worker
```

首次增加新路由时先运行一次 Vite 构建生成路由树，再运行 TypeScript 检查。当前生成的路由树已包含目录页。

回归与真实端到端验收：

```powershell
.venv/Scripts/python.exe scripts/module1_demo.py test
.venv/Scripts/python.exe scripts/module2_demo.py acceptance
```

`acceptance` 仅接受预期的 127.0.0.1 演示端口，保留用户自定义范围，使用真实 HTTP API 和独立 Worker。首次为五库保存本模块的三个合成对象；随后仅在 `demo_sales.m02_orders` 临时增加 `m02_acceptance_note`、修改金额注释，验证差异后恢复原结构，保留历史。运行记录写入 `.local/module2-verification.json`。

API/Worker 日志分别为 `.local/api.log`、`.local/api.err.log`、`.local/worker.log`、`.local/worker.err.log`；PID 在对应 `.pid` 文件中。停止进程前须核对命令属于本项目 `module1_demo.py api/worker`，避免影响其他服务。没有 Worker 时任务会保持排队，页面提供检查同步服务的提示。

Docker 部署的 `compose.yml` 已添加 `catalog-worker`，复用 backend 镜像与环境配置。部署端先执行 Alembic 迁移，再启动 API/Worker；当前五库采集在 Windows 驱动环境实测，尚未重做 Linux 容器驱动部署验证。

## 6. 建议验收步骤

1. 打开目录，切换五个数据源，确认各有 2 张表、1 个视图、9 个字段。
2. 选择“经营分析演示库”，搜索“金额”，检查仅匹配订单；清空搜索后选择“视图”，检查汇总视图的输出字段。
3. 选择订单，查看金额字段的 `numeric(12,2)`、中文注释、可空性与主键图标。
4. 打开“关联 1”，确认两条字段映射属于一个复合外键，提示必须一起匹配。
5. 打开“配置范围”，取消客户表并保存；确认当前目录立即隐藏客户表与对应关联。随后重新选回客户表并同步恢复。
6. 点击“立即同步”，观察排队/运行直至完成；重复点击受活动任务限制。没有结构变化时历史显示 0 项变更。
7. 在 PostgreSQL“同步记录”展开历史，查看临时验收字段的新增/移除及金额注释的变更前后内容。
8. 切换达梦，查看订单的元数据完整性提示。当前外键字段受限应作为本次验收的已知边界。

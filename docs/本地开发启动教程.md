# LightSQL 本地启动教程

本项目的推荐本地方式是 Docker 全容器启动。只需要安装并启动 Docker Desktop，不需要在 Windows 里分别启动 Python、Node、Bun、API 和三个 Worker。

## 第一次启动

在项目根目录打开 PowerShell：

```powershell
Set-Location D:\Projects\LightSQL
docker version
docker compose version
.\scripts\start-local.ps1
```

脚本会自动完成以下工作：

1. 创建本地配置文件 `.local\startup.env`，自动生成安全的管理员密码、数据库密码、签名密钥和数据加密密钥。
2. 构建后端镜像和前端静态资源。
3. 启动 PostgreSQL、API、目录同步 Worker、查询 Worker 和外部任务 Worker。
4. 执行数据库迁移和首个管理员初始化。
5. 等待健康检查通过。

启动成功后访问：

- 系统：http://localhost:18000
- API 文档：http://localhost:18000/docs
- 健康检查：http://localhost:18000/api/v1/utils/health-check/

管理员邮箱和初始密码写在 `.local\startup.env` 的 `FIRST_SUPERUSER` 与 `FIRST_SUPERUSER_PASSWORD`。这个文件已被 Git 忽略，不要提交或发送给别人。

如果 PowerShell 阻止执行脚本，可以使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

## 配置密码和端口

所有本地配置集中在 `.local\startup.env`。首次启动后可以编辑：

```powershell
notepad .local\startup.env
```

常用配置如下：

| 配置项 | 用途 |
| --- | --- |
| `FIRST_SUPERUSER` | 首个管理员邮箱 |
| `FIRST_SUPERUSER_PASSWORD` | 首个管理员密码；只在创建或重置管理员时使用 |
| `POSTGRES_PASSWORD` | LightSQL 元数据库密码 |
| `LIGHTSQL_PORT` | 本机访问端口，默认 `18000` |
| `SECRET_KEY` | 登录令牌签名密钥，必须长期保留 |
| `DATASOURCE_ENCRYPTION_KEY` | 数据源密码、模型密钥等敏感配置的加密密钥，必须与数据库一起备份 |
| `DATASOURCE_ALLOWED_HOSTS` | 允许接入的业务数据库主机，填写 JSON 数组 |
| `MODEL_GATEWAY_ALLOWED_BASE_URLS` | 非预设模型服务地址白名单，填写 JSON 数组 |

修改端口或环境变量后重启：

```powershell
.\scripts\start-local.ps1 -Action restart
```

编辑密码时建议使用字母、数字、下划线、短横线和点，避免把 `#`、引号或换行写进 `.env` 值。随机生成的密码已经符合这个规则。

## 忘记管理员密码

编辑 `FIRST_SUPERUSER_PASSWORD` 后执行一次：

```powershell
notepad .local\startup.env
.\scripts\start-local.ps1 -Action reset-admin
```

该命令只重置 `FIRST_SUPERUSER` 对应账号的密码，不会删除业务数据。之后可以直接用新密码登录。

## 忘记数据库密码或丢失配置

PostgreSQL 会把密码写入数据卷。仅修改 `POSTGRES_PASSWORD` 不会改变已有数据卷里的密码；如果原配置文件丢失且没有备份，旧数据卷无法通过新密码解锁。

纯本地开发、无需保留旧用户和主题时，可以显式重置当前项目的数据卷：

```powershell
.\scripts\start-local.ps1 -ResetData
```

这个选项会删除当前 `LIGHTSQL_PROJECT_NAME` 对应的容器和元数据库卷，然后按 `.local\startup.env` 重新初始化。它不会删除其他 Compose 项目或业务数据库卷。执行前请确认不需要旧数据。

## 日常使用

```powershell
# 启动；默认会重新构建镜像
.\scripts\start-local.ps1

# 只启动已有镜像，省略构建
.\scripts\start-local.ps1 -NoBuild

# 查看状态
.\scripts\start-local.ps1 -Action status

# 查看最近日志
.\scripts\start-local.ps1 -Action logs

# 停止并保留数据
.\scripts\start-local.ps1 -Action stop
```

不要用 `docker compose down -v` 做日常停止，这会删除数据库卷。升级代码时再次运行默认启动命令即可，`prestart` 会执行迁移。

## 数据源和模型配置

登录后先在“数据源”登记只读业务数据库，测试连接后执行目录同步；再创建并发布业务主题，给普通用户配置主题成员资格和查询权限。自然语言问数还需要在“模型配置”填写模型服务地址、模型名和 API Key。API Key 存在数据库的加密字段中，不要放入前端 `VITE_*` 配置。

如果业务数据库运行在宿主机上，容器内不要填 `localhost`，应使用 `host.docker.internal`，并把主机名加入 `DATASOURCE_ALLOWED_HOSTS`。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| Docker 没有 Server 信息 | 启动 Docker Desktop，确认使用 Linux 容器 |
| 页面能打开但登录失败 | 检查 `.local\startup.env`，忘记管理员密码时运行 `-Action reset-admin` |
| `password authentication failed` | 配置文件与已有数据库卷不匹配；恢复旧配置，或确认数据可删除后运行 `-ResetData` |
| Worker 一直重试 | 运行 `-Action logs`，确认数据库 healthy 且三个 Worker 都是 Up |
| 端口 18000 被占用 | 修改 `LIGHTSQL_PORT` 后运行 `-Action restart` |
| 启动超时 | 运行 `docker compose --env-file .local\startup.env -f compose.local.yml logs --tail 100` 查看具体服务日志 |

## 停止和备份

停止前保留 `.local\startup.env`。备份元数据库时，必须同时备份 `DATASOURCE_ENCRYPTION_KEY`；没有原密钥无法解密旧数据源密码和模型配置。`.local`、Docker 卷和日志均为本机数据，不应提交到 Git。

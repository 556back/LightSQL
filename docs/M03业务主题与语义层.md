## 2. 已实现的行为

| 能力 | 实际行为 |
|---|---|
| 主题 | 名称、说明、业务责任人、IANA 时区、启停；绑定单个数据源 |
| 数据模型 | 从已授权且已同步的目录选表或视图，记录业务粒度和目录主键 |
| 维度 | 稳定标识、名称、说明、别名、模型与列映射、类型、时间语义、敏感标记 |
| 指标 | 求和、行数、去重计数、均值、最大最小值、两个基础指标的比率；单位、口径、默认时间、允许维度、固定过滤、可累加性 |
| 固定过滤 | 等于、属于集合、大小比较、左闭右开区间、空值判断；验证值数量和数据库字段类型 |
| 关联 | 人工声明模型间字段配对、基数和连接方式；支持复合键；首期只允许多对一及可验证的一对一 |
| 实体词典 | 业务名称与多个别名映射到一个真实编码；按实体维度识别冲突 |
| 工作区 | 分类表单编辑和搜索；应用到工作区后统一保存；离开时保护未保存修改；可导出工作区 JSON 备份 |
| 校验 | 返回错误或提示，以及草稿修订与目录版本；结构完整但存在业务风险的配置不能发布 |
| 发布 | 独立不可变版本、发布说明、变更摘要；每次发布重新校验最新源配置和目录 |
| 恢复 | 历史版本恢复到草稿，重新校验发布后形成新版本；保留全部历史 |
| 导入导出 | JSON/YAML 草稿或历史版本导出；导入覆盖草稿；拒绝重复键、YAML 锚点/标签、未知字段和超限文件 |
| 成员 | 管理员显式分配普通用户，最多 200 人；保存授权或撤销立即对后续请求生效 |
| 访问隔离 | 普通成员仅见已授权且已发布主题；不提供草稿、物理映射、实体编码或管理员导出接口 |
| 操作记录 | 创建、保存、导入、发布、恢复、成员修改、删除写入 TopicAudit；历史发布记录不可删除 |

主题名称、说明、启停和成员授权是主题级管理信息，保存后立即生效；语义定义中的责任人、时区、指标等通过版本发布生效。删除只允许尚未发布的主题。已发布主题以停用方式退役，保留发布记录及其引用的数据源。

## 3. 发布与失效规则

1. 源配置启用，授权范围已经同步；模型对象和引用字段仍在当前目录。
2. 声明的模型主键与目录一致。关联目标字段必须覆盖完整主键，不能只写复合主键中的一列；一对一还要求起点覆盖完整主键。
3. 禁止一对多、多对多、环状关联；从指标到允许维度、时间维度和过滤维度必须存在唯一的有向路径。
4. 指标聚合与字段类型匹配。比率的分子、分母和比率本身使用相同模型、固定过滤和时间口径；按聚合结果相除，分母为零返回空值。
5. 均值、去重、比率、最大最小值标记为不可累加。半可加指标必须声明禁止跨越累加的维度。
6. 时间戳维度必须声明 UTC 或主题本地时间语义；固定日期过滤必须使用 ISO 日期，区间下界小于上界。
7. 指标和维度标识、名称与别名不能产生歧义。实体别名按维度限定，只能指向一个真实编码；数值 `101` 与 `101.0` 视为同一编码。物理标识及过滤/实体字面值保留大小写和首尾空格。
8. 敏感维度不能标记为允许外发。主题与字段外发许可均默认关闭，维度值的外发许可固定为关闭。

发布事务按照数据源 → 目录状态 → 主题的顺序加行锁，检查预期修订并生成新版本。所有草稿、成员和恢复操作检查 `expected_revision`，旧修订返回 409，防止覆盖他人的修改。

发布版本保存源修订、范围修订、目录版本及引用字段结构摘要。读取已发布目录时重新核对：使用到的列类型、可空性、主键或授权范围变化后，状态变为“需重新校验”，业务目录返回 409，等待修订并重新发布。仅增加未引用的列或修改目录注释，不会使发布版本失效。范围变化采取保守失效策略，即使只新增不相关对象，也需重新发布确认。

缺少主键的视图可作为单表模型，但不能作为关联的唯一侧。缺少时间维度产生提示，后续不能直接回答该指标的时间范围问题。

## 4. 示例口径

“销售经营分析”配置 2 个模型、10 个指标、5 个维度、1 个过滤、1 个关联和 4 个词条。

- 模型：`demo_sales.m03_orders`（每行一单）、`demo_sales.m03_customers`（每行一个租户下的客户）。
- 关联：`tenant_id + customer_id` 完整配对，多对一左连接。不同租户刻意使用相同客户编号，便于后续检查错误关联产生的重复统计。
- 指标：销售总额、退款金额、净销售额、支付订单数、最高/最低订单金额、单均退款金额、成交渠道数、客单价、退款金额占比。
- 统一过滤：订单状态为已支付。金额与退款均按原订单日期归属，退款比例为 0–1 数值，单位为“比例”。
- 维度：订单日期、销售渠道、订单状态、客户区域、客户；客户标记为敏感。
- PostgreSQL 中预置 3 个客户、5 笔合成订单，其中 1 笔已取消；M03 页面不执行这些业务查询。

原 M02 的 3 个目录对象保留，另加入上述两个合成对象。PostgreSQL 当前目录共 5 个对象、22 个字段；其余四库仍保留 M02 的 3 个对象、9 个字段。

## 7. 当前边界与下一模块

本模块负责语义配置与静态结构约束，尚不生成 SQL、读取业务结果或调用外部模型。口径说明是否符合实际业务、人工配对字段是否语义相等、主键约束在源库是否可信仍需业务和 DBA 确认。暂不支持任意计算表达式、跨源主题、桥表多对多、非主键唯一约束推导以及多层比率嵌套。

外发开关在本模块保存为配置，实际模型上下文组装与外发检查在 M05 落地；行级组织/租户授权、执行时再次检查权限、参数类型和时区转换在 M04 落地。固定业务过滤不是用户行级访问控制。源库真实权限变化需要重新同步目录才能反映在此模块。

验收后继续 M04：绑定语义版本的查询计划、五库参数化编译与方言矩阵、查询权限、超时/取消/行数限制、结果类型与执行审计。
